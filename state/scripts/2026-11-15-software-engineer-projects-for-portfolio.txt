[PART 2: THE PROJECT - STEP BY STEP]

So what is this project? It is a fully functional To-Do application, but with a twist. It will allow a user to sign up, create tasks, mark them as complete, and—here is the key part—those tasks will persist even if you refresh the page or close the browser. Most beginners build a To-Do app that loses data the moment you refresh. We are going to beat that. We are going to use a database. Specifically, we are going to use MongoDB, a NoSQL database, because it is incredibly flexible for beginners, and we are going to deploy the whole thing using Node.js and Express on the back end, and React on the front end.

Step one: Setting up the back end. Open your terminal. We are going to create a new directory. Type 'mkdir taskmaster' and hit enter. Now type 'cd taskmaster' and hit enter. We need to initialize a Node.js project. Type 'npm init -y'. This creates a default package.json file. Now, we need our core dependencies. Type 'npm install express mongoose cors'. Express is the web server framework. Mongoose is the tool that lets us talk to MongoDB. CORS allows our front end to talk to our back end without getting blocked by browser security.

Step two: Creating the server file. Create a new file called 'server.js'. This is the brain. We need to import Express, and we need to import the CORS middleware. Type: 'const express = require("express");'. 'const app = express();'. Type: 'const cors = require("cors");'. Type: 'app.use(cors());'. This one line enables our front end to talk to our back end. Now, we need to set up the port. Type: 'const port = 5000;'.

Step three: Connecting to the database. We are going to create a separate file for our database connection. Create a new file called 'db.js'. This is where the magic happens. We are going to write a small piece of code that connects our application to MongoDB. Type: 'const mongoose = require("mongoose");'. Then, we need the connection string. If you have a MongoDB Atlas account—which is free—you can get a connection string from their website. Type 'mongoose.connect("YOUR_MONGODB_CONNECTION_STRING_HERE");'. That is the exact command. If you are following along, replace that placeholder with your actual string. Now, add a small listener to make sure we know if it works. Type '.then(() => { console.log('DB connected successfully'); })'. And finally, we need to export this so our server can use it. Type 'module.exports = mongoose.connection;'.

Step four: Creating the model. In the same folder, create a file called 'taskModel.js'. This defines what a task looks like. We need a title, a status, and a timestamp. Type: 'const mongoose = require("mongoose");'. Then, define the schema. Type: 'const taskSchema = new mongoose.Schema({ title: { type: String, required: true }, completed: { type: Boolean, default: false }, createdAt: { type: Date, default: Date.now } });'. Notice the 'required: true' for the title. This ensures no task can be saved without a name. Now, we create the model. Type: 'const Task = mongoose.model("Task", taskSchema);'. And export it. Step five: Building the API routes. Create a file called 'taskRoutes.js'. This is where we define the commands the front end can use. We need to import Express and our Task model. [PART 5: COMMON MISTAKES AND PRO TIPS]

Now, I want to save you from the most common mistakes I see beginners make with this exact project.

Mistake number one: Forgetting to add the CORS middleware. If you try to run your React app on port 3000 and your Node server on port 5000, your browser will block the request. It says, 'Hey, these two different ports are not allowed to talk!' The fix is easy. In your server.js, right after you import Express, type 'const cors = require("cors");'. Then, type 'app.use(cors());'. This one line fixes the connection instantly.

Mistake number two: Using the wrong MongoDB connection string. If you get an error saying 'Authentication failed', check your string. If you are using MongoDB Atlas, make sure your IP address is whitelisted in the network access settings on the Atlas dashboard. It is a common setting that trips people up.

Mistake number three: Not handling errors on the front end. If the server is down and you try to fetch data, your app might crash. Always use the '.catch' block I showed you earlier. It keeps your app stable.

Pro tip number one: Use environment variables. Never, ever hardcode your database password into your code if you are going to share it on GitHub. Use a .env file. There are tutorials on how to set that up, but the rule of thumb is: keep your secrets safe.

Pro tip number two: Add a 'delete' button. Recruiters love it when you go beyond the minimum. Add a route that deletes a task by its ID. It shows you can manage data lifecycle.
