Step 1: The Foundation - Understanding the Prompt
Before we type anything, let's talk about the interview mindset. When an interviewer asks about a command, they aren't just testing your memory; they are testing your ability to navigate a system. The very first step is to recognize that Linux is case-sensitive and that commands usually have options, called flags, that change what they do. Think of a command like a Swiss Army knife; the base tool is the command, and the flags are the attachments that make it do specific jobs. This context will help you answer the 'what does this do?' question every time.

Step 2: pwd - Print Working Directory
Our first command is 'pwd'. In an interview, you might be asked, 'How do you know where you are in the file system?' The command is simple: type 'pwd' and press Enter. Spoken clearly: type: pwd. When it works, you will see a full file path printed on your screen, showing you exactly which directory you are currently sitting in. It is the 'You Are Here' map of Linux. A common mistake students make is confusing 'pwd' with 'ls'. Remember: 'pwd' tells you where you are; 'ls' shows you what is inside that spot.

Step 3: ls - List
Now, let's look at 'ls'. This is the most frequently asked command: 'List the files in a directory'. To use it, type 'ls' and press Enter. Spoken clearly: type: ls. When it works, you will see a list of filenames and folders in your current directory. Here is the pro tip that separates freshers from the rest: add the '-l' flag. Type 'ls -l' and press Enter. This gives you a 'long listing', showing you permissions, the owner, the size, and the date modified. If an interviewer asks about permissions, you can immediately point to the 'ls -l' output to explain read, write, and execute. **Important:** In Linux, flags start with a dash (-). Do not use a forward slash (/), as that is Windows syntax and will cause errors.

Step 4: cd - Change Directory
Next is navigation. 'cd' stands for Change Directory. If you are asked how to move between folders, the command is 'cd' followed by the folder name. Spoken clearly: type: cd Documents. When it works, your prompt will change, and if you type 'pwd' again, you will see you are now inside the Documents folder. The tricky part interviewees often stumble on is the 'cd ..' command. The two dots mean 'go up one level'. Type 'cd ..' and press Enter to go back to the parent directory. **Note:** Typing 'cd /' takes you to the root of the entire system. To get to your personal home folder, just type 'cd' with no arguments, or use the tilde symbol '~'.

Step 5: mkdir - Make Directory
Creating a new folder is essential. If asked how to create a new folder, the command is 'mkdir'. Spoken clearly: type: mkdir NewFolder. When it works, if you type 'ls', you will see 'NewFolder' appear in the list. The advanced interview tip here is nesting. If you need to create a folder inside another folder that doesn't exist yet, use 'mkdir -p'. Type 'mkdir -p Projects/Website'. The '-p' flag means 'create parent directories as needed'. Without the '-p', if 'Projects' didn't exist, the command would fail with an error saying the parent directory does not exist.

Step 6: rm - Remove (Delete)
Deleting files is a high-stakes topic in interviews. The command is 'rm'. Spoken clearly: type: rm filename.txt. When it works, the file disappears. But here is the critical part most freshers get wrong: 'rm' deletes permanently by default. There is no trash can in the command line by default. If an interviewer asks about safety, you must mention the '-i' flag for interactive mode. Type 'rm -i filename.txt' and it will ask you 'remove file?' before doing it. **Critical Warning:** The most common error is typing 'rm -rf' on an important folder. '-r' stands for recursive, deleting folders and all contents, and '-f' forces it without asking. Never use 'rm -rf' unless you are absolutely sure.

Step 7: cp - Copy
Copying files is the next logical step. The command is 'cp'. Spoken clearly: type: cp source.txt destination.txt. When it works, you now have two copies of the file. The interview angle here is the path. You can copy across directories by giving full paths. Type 'cp /home/user/file.txt /tmp/'. **Important:** Remember, the source comes first, then the destination. Also, if you want to copy a whole folder and keep the structure, add the '-r' flag: 'cp -r Folder1 Folder2'.

Step 8: mv - Move or Rename
'mv' is versatile. It can move a file from one place to another, or rename it. Spoken clearly: type: mv oldname.txt newname.txt. When it works, the file is renamed. To move it to a different folder: type 'mv file.txt /home/user/Documents/'. **Pro Tip for Interviews:** You can use 'mv' to effectively cut and paste. **Critical Warning:** The common error is trying to move a file to a location that doesn't exist, which will result in the file disappearing from the original spot and failing to appear in the new spot. Always check the destination exists, or use 'mv -i' to prompt if a file with that name already exists.

Step 9: cat - Concatenate
'cat' is used to view the content of a file or combine files. Spoken clearly: type: cat filename.txt. When it works, the text of the file will scroll onto your screen. **Interview Trick:** Using 'cat' to combine files. Type 'cat file1.txt file2.txt > combined.txt'. This takes the content of both files and creates a brand new file called 'combined.txt'. **Crucial Warning:** A single '>' overwrites the destination file completely. If you want to append to a file without wiping it, you use '>>'. Two greater signs.

Step 10: grep - Global Regular Expression Print
The final command, and arguably the most powerful for interviews, is 'grep'. It searches for text inside files. If asked how to find a specific word in a log file, the command is 'grep'. Spoken clearly: type: grep "error" filename.log. When it works, the terminal will highlight every line containing the word 'error'. **Pro Tip:** The '-i' flag for case insensitivity. Type 'grep -i "error"' so it finds 'Error', 'ERROR', or 'error'. **Critical Warning:** Ensure you use double quotes around the search term. Type grep error without quotes, and the shell may interpret the argument incorrectly or fail to search the intended text. Always quote your search patterns to avoid shell interpretation errors.
